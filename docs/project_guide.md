# 结构 配置与评价

## 数据流

```text
图像与框标签 → 尺寸/类别配置 → Backbone → 多尺度融合 → Detect
                  → 置信度筛选与NMS → Precision Recall AP/mAP
```

典型输入为 `[B,3,H,W]`，640×640输入的P3/P4/P5空间尺寸通常为80×80、40×40、20×20。实际通道数由网络配置及宽度倍率决定。Concat前需对齐空间尺寸，下采样细节损失与尺度融合的取舍需要通过统一协议评价。

## 网络配置与HG

`yolohg.yaml` 每层按 `from, repeats, module, args` 描述来源、重复、模块和参数。`ultralytics/nn/tasks.py::parse_model` 将其转换成真实网络。

`block.py::HG.forward` 将多路输入交给PyramidPoolAgg对齐，经卷积、AIFI和C2f交互，按通道切成两路，其中一路上采样。返回值为列表；下游模块与解析器需要明确选择各支并传播尺寸、通道信息。当前配置在这部分不完整，尚未验证整个修改网络可构建。

## 版本与资源

源码 `__version__` 为8.2.14，已有研究记录中还存在其他版本命名。仅凭模块名称不能将当前快照认定为另一个YOLO版本。原始最终检查点、数据和对应验证日志未提供，模型构建、加载与评价需要分别检查。

## 数据与评价

屏幕异常采用黑屏、花屏、红/蓝/白屏5类标签。数据YAML的类别数、编号与标注应一致；上游网络的默认80类不能当作实际业务类别配置。视频相邻帧可能造成泄漏，划分时应按视频、设备或采集批次控制重复场景。

NMS用于去除重复预测；IoU用于衡量区域重叠；AP/mAP按评价协议统计定位与类别结果。mAP50与mAP50-95不是同一指标，框与掩码评价也不能互换。缺少可匹配的原始验证日志时，不以研究记录中的单个高分作为已验证基准。
